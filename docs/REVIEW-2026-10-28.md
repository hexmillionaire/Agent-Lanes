# Community investigation — 2026-10-28

This is a dated review of explicit developer reports, current primary documentation and existing implementations, not a survey or a claim about how frequently a problem occurs. GitHub issue state, creation/update dates and repository archival flags were checked through GitHub's API on October 28, 2026. A report remaining open does not establish that every current installation reproduces it.

## Recommendation: Worktree Stamp

Build a small, provider-neutral `worktree-stamp capture/check` utility that detects whether included Git state differs from a saved content fingerprint. It should include committed identity, staged entries, tracked on-disk bytes and nonignored untracked bytes. A dirty worktree must not keep the same identity merely because it was already dirty. This is a freshness observation, not proof that a command ran, tests passed, tests were adequate or a task was completed.

The focused developer request is [Claude Code #104504](https://github.com/anthropics/claude-code/issues/104504), opened **October 23**, updated **October 23**, and **open** when checked. It asks for later edits to invalidate earlier test claims and for real process exit status to survive pipelines. Its numerical findings describe the reporter's own sessions; they are not community prevalence estimates. Worktree Stamp addresses only content freshness. It will not parse transcripts, run tests or repair shell pipelines. The separate [#103117](https://github.com/anthropics/claude-code/issues/103117), opened/updated **October 18**, also **open**, describes an inherited PowerShell exit value mistaken for a fresh test result; it reinforces the need to keep captured facts and inferred success separate.

### Actual gap and prior art

[Agent Done Or Not](https://github.com/mohamedzhioua/agent-done-or-not) is a broader command-capture, policy, CI and stop-hook solution. Its repository was not archived and last pushed **October 12** when checked. At exact revision [f865d82](https://github.com/mohamedzhioua/agent-done-or-not/blob/f865d82b3df8d28a64c4dd799bde23ea239e68c4/done-gate.sh#L88-L90), `git_tree()` reads `HEAD^{tree}` and `git_dirty()` records a boolean. Its [drift comparison](https://github.com/mohamedzhioua/agent-done-or-not/blob/f865d82b3df8d28a64c4dd799bde23ea239e68c4/done-gate.sh#L176-L193) checks changed HEAD and clean-to-dirty transition. Therefore two different dirty file contents under the same HEAD can pass that particular comparison. This is an implementation-specific freshness gap, not a claim that the entire tool is ineffective.

Content fingerprints themselves are existing practice. [oh-my-hermes](https://github.com/rlaope/oh-my-hermes/blob/main/docs/WORKING-TREE-FINGERPRINT.md) already implements a conservative final-working-tree identity within a larger goal/quality-evidence suite; staging unchanged final bytes deliberately does not change that identity. [Groundtruth](https://github.com/akahkhanna/groundtruth) also has stale-by-tree transcript sensors. A standalone stamp that includes staging state is a smaller integration primitive, not a novel invention or a replacement for those tools. [Backcheck](https://github.com/VectorInstitute/backcheck) audits Claude transcripts and stale claims; its repository is **archived** as checked October 28, despite a last push on **October 14**, so it should not be described as maintained.

### Small initial contract

- Read-only `capture` and `check`, stdout JSON by default for capture, no model calls, no test or arbitrary command execution, no hooks or configuration writes. Save the artifact outside the repository so the output does not become a new input.
- Versioned bounded JSON containing relative path metadata and digests, with no raw file contents, remote URLs or absolute repository paths. Hash tracked regular-file bytes even when Git's status flags would hide an edit; include index mode/object identity and nonignored untracked paths/content.
- Two complete observations must agree. Detect observed replacement/write races and fail indeterminate; do not call the result an atomic snapshot or protection against a malicious same-user writer.
- Explicit exclusions: ignored files, external state, dependencies outside included paths, environment, interpreter/compiler identity, test selection/adequacy and test results. Reject symlinks, special files, gitlinks/submodules, conflicts, unreadable inputs and capacity excess rather than reporting them fresh.
- Exit `0` for matching included state, `1` for stale included state, `2` for invalid/unsupported/indeterminate observation. No local receipt authenticity or semantic-correctness guarantee.

Meaningful fixture checks: dirty-to-dirty same-path edit, index-only change with identical worktree bytes, nonignored untracked content edit, deletion/rename, linked Git worktree, unchanged repeat capture, ignored-file exclusion, spaces/Unicode/control characters represented safely, hostile `GIT_*` redirection, symlink/special-file refusal, size/count/JSON bounds and observed races. Package smoke should exercise an installed CLI. CI should cover Linux, macOS and Windows on Node 24 and 26, plus the Node 24.8 minimum.

On October 28, both public npm names `worktree-stamp` and `@hexmillionaire/worktree-stamp`, and GitHub `hexmillionaire/worktree-stamp`, returned 404. This is a point-in-time availability check, not a reservation.

## Why the other candidates should wait

### Instruction/config diagnostics

[Codex #13386](https://github.com/openai/codex/issues/13386), opened **March 3**, updated **October 24**, remains **open** and requests visibility when instruction content exceeds the byte budget. [#25884](https://github.com/openai/codex/issues/25884), opened **June 2**, updated **September 29**, remains **open** and explicitly asks which instruction sources are active. Its main complaint is application/retention, which a filesystem linter cannot guarantee.

[Official OpenAI documentation](https://learn.chatgpt.com/docs/agent-configuration/agents-md) already describes override precedence, per-directory discovery, the default combined 32 KiB budget, restart behavior, and ways to inspect loaded sources/logs. [Official prompting guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) also recommends keeping instructions contextual and trimming obsolete requirements. Existing [agents-md-doctor](https://github.com/ItsHege/agents-md-doctor), [claude-md-doctor](https://github.com/agent-clinic/claude-md-doctor), [agentlint](https://github.com/kcotias/agentlint) and [AsItIs](https://asitis.app/rules/codex-chain-over-budget) already cover structural instruction diagnostics and/or chain budgets. The first three repositories were not archived when checked and had recent pushes. [Claude's own documentation](https://code.claude.com/docs/en/memory#audit-your-instruction-files) now includes `/doctor prompt-audit` and instruction-loading diagnostics. Another generic doctor would duplicate substantial existing work and could imply semantic guarantees it cannot provide.

**Later idea 1:** a fictional instruction-discovery fixture pack and JSON adapter for existing diagnostics, covering override/fallback/byte-budget cases with expected source provenance. Prefer contributions or an integration with a maintained doctor; do not claim to test whether a model obeys a rule.

### MCP discovery/pagination capture

[Inspector #2220](https://github.com/modelcontextprotocol/inspector/issues/2220) was opened **September 2** and **closed completed September 6**. It concerns empty-string cursors being dropped by some list adapters; it is historical regression evidence, not an outstanding unsupported feature. Current official [Inspector fixtures](https://github.com/modelcontextprotocol/inspector/blob/main/docs/test-servers.md) already exercise empty cursors and multi-page lists, while [its implementation notes](https://github.com/modelcontextprotocol/inspector/blob/main/specification/v2_new_spec_impact.md) explain current SDK aggregation and raw per-page requests. [Inspector's CLI](https://github.com/modelcontextprotocol/inspector/blob/main/clients/cli/README.md) already lists tools and offers strict schema diagnostics. Another general live collector should not be the first new repository.

**Later idea 2:** an Inspector-to-MCP-Surface artifact adapter plus minimized pagination regression cases, preserving cursor completeness and capture provenance while leaving transport/auth/server launch to the official client. Add it only if a concrete current capture format is missing; current SDK/Inspector overlap must be rechecked before implementing.
